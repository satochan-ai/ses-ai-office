# SES AI Office

SES営業・採用・BP開拓・案件マッチング・稼働フォローを、複数のAI社員が分担して支援するAIオフィスのフロントエンドMVPです。

## 主な特徴

- AI社員7名による業務分担
- ビジュアルAIオフィス
- 営業判断Dashboard
- 新着案件から提案準備までの連携デモ
- 顧客・BP開拓
- 案件と要員のマッチング
- 採用・稼働フォロー
- 営業分析
- PC・スマートフォン対応

## AI社員

| AI社員 | 主な役割 |
| --- | --- |
| AI営業Mgr | 営業全体を見渡し、優先順位、停滞、商機を統合判断します。 |
| AI新規開拓担当 | 新規顧客候補を調査し、アプローチ先と初回連絡を整理します。 |
| AIBP開拓担当 | BP企業の得意領域、商流、保有人材を整理して関係構築を支援します。 |
| AIマッチング担当 | 案件条件と要員情報を照合し、提案候補と不足条件を抽出します。 |
| AI採用担当 | 応募・スカウト・面談の進捗を整理し、選考停滞を検知します。 |
| AIフォロー担当 | 稼働中エンジニアの週報、契約更新、リスク兆候を確認します。 |
| AI分析担当 | 営業・採用ファネル、商談化率、NG理由などを横断分析します。 |

## 画面構成

### ビジュアルAIオフィス

URL：`http://localhost:3003/`

役割：

- AI社員の稼働状況確認
- 各部屋の現在作業確認
- AI社員への個別指示
- 連携デモの開始

### 管理Dashboard

URL：`http://localhost:3003/dashboard`

役割：

- KPI確認
- 優先タスク確認
- 新規開拓ファネル
- 顧客・BPの停滞・商機確認
- 案件・採用進捗
- AI実行ログ
- デモ結果確認

## デモシナリオ

デモ名：`新着案件から提案準備まで`

1. 新着Java案件を受信
2. 案件条件と類似実績を分析
3. 要員32名を照合
4. 候補者3名を抽出
5. 営業優先順位を決定
6. 推薦文を作成
7. 提案準備完了

通常速度は約28秒、高速デモは約8秒です。実行中は担当AIの状態、吹き出し、部屋の強調、進捗、実行ログが連動します。

## デモの操作方法

1. `npm run dev`で起動
2. `http://localhost:3003/`を開く
3. 「デモを開始」を押す
4. 通常速度または高速デモを選択
5. AI社員と各部屋の変化を見る
6. 完了モーダルを確認
7. 「管理ダッシュボードで確認」を押す
8. Dashboardで数値・優先タスク・ログの反映を確認
9. 必要に応じてデモ結果をリセット

## セットアップ

```bash
npm install
npm run dev
```

起動ポートは3003固定です。ブラウザで `http://localhost:3003/` を開いてください。

その他のコマンド：

```bash
npm run lint
npm run build
npm run start
```

## 現在の実装範囲

このリポジトリはフロントエンドMVPです。画面、AI社員の操作、連携デモ、Dashboard反映はブラウザ上で動作します。デモ結果は同一タブの `sessionStorage` に一時保存されます。

実装済み：

- ビジュアルAIオフィスと管理Dashboard
- AI社員詳細と指示実行の仮動作
- モックデータによるKPI、タスク、案件・要員表示
- AI社員の連携デモとDashboard反映
- PC・スマートフォンのレスポンシブ対応

以下はモックデータ・モック動作です。

- AI社員の判断、分析、推薦文作成
- 案件・要員・候補者・顧客・BP情報
- AI実行ログ、KPI、進捗、通知
- 個別指示と一括指示の処理結果

以下は未実装です。

- OpenAIなどの生成AI API連携
- メール、カレンダー、CRM連携
- 実際の案件受信、要員データベース検索、提案送信
- バックエンド、永続データベース、認証・権限管理
- 本番運用向けジョブ実行、監査ログ、エラー監視

## 注意事項

- 現在はフロントエンドMVPです。
- デモ結果は `sessionStorage` に保存され、ブラウザタブを閉じると消えます。
- 画面内の企業名、人物名、案件、数値はデモ用であり、実在データではありません。
- 個別指示や連携デモを実行しても、外部へのメール送信やデータ登録は行いません。
